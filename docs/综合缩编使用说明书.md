## 1. 概述

### 1.1 功能定位

综合缩编是 MPQIS 平台的制图综合模块，实现从大比例尺（如 1:10000）到目标比例尺（如 1:50000）的自动化地图缩编。覆盖五大处理阶段、共 20 个算法，支持 15 种图层大类（A～N 三阶复合码体系）。

### 1.2 架构总览

```
┌──────────────────────────────────────────────────┐
│              GeneralizationConfigDialog            │
│  数据源选择 → XML 配置 → 输出目录 → 执行          │
└─────────────────────┬────────────────────────────┘
                      │ ParsePipelineXml()
                      ▼
┌──────────────────────────────────────────────────┐
│               PipelineExecutor                    │
│                                                   │
│  Stage 1: preprocess  ──► TempDir_1 (gpkg/shp)   │
│  Stage 2: merge       ──► TempDir_2              │
│  Stage 3: simplify    ──► TempDir_3              │
│  Stage 4: select      ──► TempDir_4              │
│  Stage 5: conflict    ──► TempDir_5              │
│                          │                        │
│                          ▼                        │
│              最终输出目录 + 多格式导出              │
└──────────────────────────────────────────────────┘
```

### 1.3 图层分类体系

| 大类 | 代码 | 子类举例 |
|------|------|----------|
| N — 自然 | N | n_mou 山体, n_hyd 水体, n_ice 冰雪地, n_oce 海洋, n_agr 农林用地 |
| A — 人工 | A | a_wac 水利, a_tra 交通, a_bld 建构筑物, a_pip 管线, a_yad 院落 |
| M — 管理 | M | m_adm 行政区划, m_gna 地名, m_nsp 国土空间规划, m_oma 其他管理区 |

表名格式: `{大类}_{子类}_{要素子类}_{几何类型}`，例如 `a_bld_afc_a.shp`。

## 2. 快速入门

### 2.1 前置条件

- QGIS 3.28 已安装，MPQIS 插件已加载
- 输入数据为 ESRI Shapefile（或可通过 ogr2ogr 从 PostGIS 导出）
- 坐标系建议为投影坐标系（如 EPSG:4548），因为算法使用米制距离参数

### 2.2 最短执行路径（5 步完成）

1. **打开对话框**: QGIS 菜单 → 综合缩编 → 综合缩编配置
2. **选择数据源**: 切换 "文件系统" / "数据库" 单选按钮，指定输入路径
3. **选择 XML 管线**: 点击 "浏览" 选择 `generalization_pipeline.xml`
4. **设置输出目录**: 指定缩编结果输出位置
5. **执行**: 点击 "执行综合缩编" 按钮

### 2.3 文件系统模式 vs 数据库模式

| 对比项 | 文件系统模式 | 数据库模式 |
|--------|-------------|-----------|
| 数据源 | 本地 SHP 目录 | PostGIS `mpqis` schema |
| 选择方式 | 浏览文件夹 | 勾选图层大类（通过 ogr2ogr 导出到临时目录） |
| 适用场景 | 小批量测试 | 生产环境、需要 SQL 查询配合 |

## 4. 管线配置 XML 详解

### 4.1 文件位置

```
QGIS插件目录\config\generalization_pipeline.xml
```

### 4.2 顶层结构

```xml
<?xml version="1.0" encoding="UTF-8"?>
<generalization_pipeline version="1.0">
    <global>       <!-- 全局参数: 数据源 + 输出 + 制图 + 日志 -->
        <input_source .../>
        <output>...</output>
        <cartographic>...</cartographic>
        <logging>...</logging>
    </global>
    <pipeline>     <!-- 管线定义: 5 个 Stage, 每个含若干 algorithm -->
        <stage id="preprocess"> ... </stage>
        <stage id="merge">      ... </stage>
        <stage id="simplify">   ... </stage>
        <stage id="select">     ... </stage>
        <stage id="conflict">   ... </stage>
    </pipeline>
</generalization_pipeline>
```

### 4.3 `<global>` 节点

#### 数据源 — 文件系统模式

```xml
<input_source type="filesystem">
    <path>D:/数据目录/shp</path>
    <format>ESRI Shapefile</format>
    <encoding>UTF-8</encoding>
</input_source>
```

#### 数据源 — 数据库模式

```xml
<input_source type="database">
    <connection host="localhost" port="5432" dbname="mpqis"
                user="mpqis_app" password="..." schema="mpqis"/>
    <layer_types>
        <type>A</type>    <!-- 建筑 -->
        <type>D</type>    <!-- 道路 -->
        <type>F</type>    <!-- 水系 -->
        <type>M</type>    <!-- 政区 -->
    </layer_types>
</input_source>
```

#### 输出设置

```xml
<output>
    <directory>D:/output/generalization_20260715</directory>
    <export>
        <format name="PostgreSQL">
            <connection host="localhost" port="5432" dbname="mpqis"
                        user="mpqis_app" password="..." schema="mpqis"/>
        </format>
        <format name="ESRI Shapefile" enabled="true"/>
        <format name="GeoPackage"    enabled="false"/>
    </export>
    <cleanup_temp>false</cleanup_temp>
</output>
```

#### 制图参数

```xml
<cartographic>
    <source_scale>1:10000</source_scale>
    <target_scale>1:50000</target_scale>
    <coordinate_system>EPSG:4548</coordinate_system>
    <area_of_interest>                <!-- 可选: 空间范围裁剪 -->
        <bbox xmin="512008" ymin="4342517" xmax="513517" ymax="4344132"/>
    </area_of_interest>
</cartographic>
```

#### 日志

```xml
<logging>
    <level>INFO</level>               <!-- DEBUG | INFO | WARNING | ERROR -->
    <output_dir>D:/output/logs</output_dir>
</logging>
```

### 4.4 通用子元素

每个 `<algorithm>` 内部可使用以下子元素（按需选用）：

| 子元素 | 用途 | 示例 |
|--------|------|------|
| `<param>` | 算法参数（键值对） | `<param name="tolerance" value="5.0" unit="m"/>` |
| `<semantic_rules>` | 语义规则（按属性分类处理） | `<rule field="ClassID" value_prefix="2307" action="merge"/>` |
| `<network_constraints>` | 网状约束（道路/管线作为合并边界） | `<constraint layer_type="a_tra" distance="5.0" unit="m"/>` |
| `<per_layer>` | 按图层类型覆写参数 | `<layer type="a_tra"><param name="tolerance" value="3.0" unit="m"/></layer>` |
| `<conflict_pairs>` | 冲突检测配对（aggressor → victim） | `<pair aggressor="a_tra" victim="a_bld" buffer="5.0" unit="m"/>` |
| `<select_rules>` | 选取规则（按属性分级保留） | `<rule field="ClassID" value_prefix="4201" min_length="0"/>` |

### 4.5 控制开关

所有 `<stage>` 和 `<algorithm>` 均支持 `enabled` 属性：

```xml
<stage id="merge" name="图斑合并" enabled="false">  <!-- 整个 Stage 跳过 -->
<algorithm name="WaterMerge" class="WaterMergeAlgorithm" enabled="false">  <!-- 单个算法跳过 -->
```

### 4.6 XML 编写规则

- **禁止** 在注释中使用 `--`（XML 规范限制），请改用 `====` 或 `----` → `——`
- `<param>` 的 `value` 总是字符串，算法内部通过 `paramBool()` / `paramDouble()` 转换
- `value_prefix` 匹配规则：检查字段值是否以此前缀**开头**（前 N 字符完全相等）
- `<semantic_rules>` 中 `action` 取值: `merge`（参与合并）/ `separate`（保持独立）/ `protect`（保护，不合并也不被覆盖）

## 5. Stage 1: 预处理与数据规范化

**Stage ID**: `preprocess`  
**目的**: 修复原始数据的拓扑/几何/属性问题，为后续算法准备干净输入。

### 5.1 TopologyFixAlgorithm — 拓扑修复

**功能**: 线段相交处打断为节点，过滤短片段，建立节点-弧段拓扑。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `snap_tolerance` | double | 0.5 (m) | 节点吸附距离，小于此值的端点合并 |
| `min_segment_length` | double | 0.01 (m) | 最短路段的长度，短于此值的片段删除 |
| `intersection_split` | bool | true | 是否在相交处自动打断 |

**内部实现**: GEOS UnaryUnion → 节点分割 → 短段过滤。

### 5.2 GeometryNormalizeAlgorithm — 几何规范化

**功能**: 修正环方向（OGC 标准）、闭合面、去重节点、删除尖刺、坐标对齐。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `fix_ring_direction` | bool | true | 外环 → 逆时针，内环 → 顺时针 (OGC) |
| `close_rings` | bool | true | 自动闭合未封闭的面环（追加首点） |
| `remove_duplicate_nodes` | bool | true | 删除连续重复坐标点（eps=1e-9） |
| `remove_spikes` | bool | true | 移除外凸尖刺（角度过小的孤立顶点） |
| `min_spike_angle` | double | 5.0 (度) | 尖刺识别阈值：转折角 < 此值 → 移除该顶点 |
| `snap_to_grid` | double | 0.001 (m) | 坐标对齐到网格，消除浮点精度问题 |

### 5.3 AttributeNormalizeAlgorithm — 属性规范化

**功能**: 统一字段编码格式、空白裁剪、空值处理策略。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `trim_strings` | bool | true | 去除字符串字段头尾空格 |
| `null_fill_policy` | string | skip | 空值策略: `skip`(保持原值) / `default`(填默认值) / `error`(报错) |
| `encoding_check` | string | UTF-8 | 编码验证标准 |

## 6. Stage 2: 图斑合并

**Stage ID**: `merge`  
**目的**: 将距离过近或共享边界的同类图斑合并，保持结构轮廓，兼顾语义规则和网状约束。

### 6.1 BuildingMergeAlgorithm — 建筑图斑合并

**功能**: 基于邻近性 + 语义相似性的建筑面聚合，支持道路/管线作为合并边界约束。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `merge_mode` | string | aggregation | `aggregation`(聚合) / `dilation`(膨胀) / `skeleton`(骨架化) |
| `merge_distance` | double | 10.0 (m) | 小于此距离的面要素合并 |
| `min_area` | double | 200.0 (m²) | 合并后面积 < 此值 → 删除 |
| `preserve_structure` | bool | true | 保持建筑群整体轮廓形状 |
| `structure_preserve_weight` | double | 0.7 | 结构保持权重 (0~1)，越大越保守 |

**语义规则** (可选):

```xml
<semantic_rules>
    <rule field="ClassID" value_prefix="2307" action="merge"/>      <!-- 2307xx类建筑 → 参与合并 -->
    <rule field="ClassID" value_prefix="2308" action="separate"/>   <!-- 2308xx类 → 保持独立 -->
    <rule field="Function" value="学校"       action="protect"/>    <!-- 学校 → 保护,不合并 -->
</semantic_rules>
```

**网状约束** (可选):

```xml
<network_constraints>
    <constraint layer_type="a_tra" distance="5.0" unit="m"/>   <!-- 道路5m内建筑不可跨越 -->
    <constraint layer_type="a_pip" distance="3.0" unit="m"/>   <!-- 管线3m内不可跨越 -->
</network_constraints>
```

**内部流程**:
1. 加载 D/E 类图层作为约束几何 (buffer 约束距离)
2. 遍历每个 SHP → 根据 semantic_rules 分类 `merge` / `separate` / `protect`
3. `merge` 组: `buffer(mergeDist/2)` → `UnaryUnion` → `buffer(-mergeDist/2)` → `minArea` 过滤
4. 合并结果与约束几何做 `Difference` 运算
5. `separate` + `protect` 要素原样写回

### 6.2 WaterMergeAlgorithm — 水系图斑合并

**功能**: 自动检测水系图层（文件名前缀 `F` 或 `n_hyd`），合并后简化岸线。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `merge_distance` | double | 20.0 (m) | 合并距离 |
| `min_area` | double | 500.0 (m²) | 最小面积阈值 |
| `preserve_shoreline_detail` | bool | true | 保持岸线细节特征 |
| `simplify_tolerance` | double | 50.0 (m) | 合并后岸线 DP 简化容差 |

### 6.3 VegetationMergeAlgorithm — 植被图斑合并

**功能**: 自动检测植被图层（文件名前缀 `L` 或 `n_agr`），支持语义规则。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `merge_distance` | double | 15.0 (m) | 合并距离 |
| `min_area` | double | 1000.0 (m²) | 最小面积阈值 |

## 7. Stage 3: 协调化简

**Stage ID**: `simplify`  
**目的**: 对点/线/面要素进行简化，保持不同要素类型之间的拓扑一致性。

### 7.1 LineSimplificationAlgorithm — 线要素简化

**功能**: Douglas-Peucker 或 Visvalingam 算法简化线要素，支持按图层类型分别设置容差。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `algorithm` | string | douglas_peucker | `douglas_peucker` / `visvalingam` / `wang_muller` |
| `tolerance` | double | 5.0 (m) | 全局简化容差 |
| `preserve_endpoints` | bool | true | 保持线要素起止端点 |
| `preserve_intersections` | bool | true | 保持与其他线要素的交点 |

**按图层覆写** (可选):

```xml
<per_layer>
    <layer type="a_tra">   <!-- 道路: 保守 -->
        <param name="tolerance" value="3.0" unit="m"/>
    </layer>
    <layer type="a_pip">   <!-- 管线: 激进 -->
        <param name="tolerance" value="8.0" unit="m"/>
    </layer>
</per_layer>
```

**内部实现**: DP 递归算法 (垂直距离法) + Visvalingam (有效面积 + set<pair> 堆排序)。

### 7.2 PolygonSimplificationAlgorithm — 面要素简化

**功能**: DP 算法简化面边界，保持面之间不重叠、不留缝隙。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `algorithm` | string | douglas_peucker | 简化算法 |
| `tolerance` | double | 5.0 (m) | 简化容差 |
| `preserve_topology` | bool | true | 保证面间拓扑一致 |
| `min_area` | double | 100.0 (m²) | 简化后面积 < 此值 → 合并到相邻面 |
| `shared_boundary_align` | bool | true | 对齐共享边界（防缝隙） |

### 7.3 PointSelectionAlgorithm — 点要素选取

**功能**: 按重要性 / 格网 / 密度选取点要素，保证点间最小距离。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `method` | string | importance | `importance`(按重要性) / `grid`(格网) / `density`(密度) |
| `importance_field` | string | AdminLevel | 重要性字段名 |
| `grid_size` | double | 200.0 (m) | 格网单元格大小 |
| `min_distance` | double | 50.0 (m) | 点间最小间距 |

## 8. Stage 4: 分要素缩编

**Stage ID**: `select`  
**目的**: 按要素大类 (A～F/J/L/M/N) 分别进行选取/化简/概括/位移。

### 8.1 RoadNetworkThinAlgorithm — 路网稀疏化

**功能**: 按等级 (国道>省道>县道>乡道) 选取道路，保持路网连通性。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `min_length` | double | 50.0 (m) | 短于此值的支路删除 |
| `deadend_prune` | bool | true | 剪除死胡同（仅一个邻居的端点段） |
| `roundabout_collapse` | bool | true | 环岛 → 单一节点 |
| `dual_carriageway_collapse` | bool | false | 双线路 → 单线（目标比例尺较大时开启） |
| `preserve_connectivity` | bool | true | 保持路网连通性（关键！不可轻易关闭） |
| `importance_field` | string | ClassID | 按等级选取的字段 |

**选取规则** (可选):

```xml
<select_rules>
    <rule field="ClassID" value_prefix="4201" min_length="0"/>       <!-- 国道 → 全部保留 -->
    <rule field="ClassID" value_prefix="4203" min_length="200.0"/>   <!-- 省道 → 下限200m -->
    <rule field="ClassID" value_prefix="4205" min_length="500.0"/>   <!-- 县道 → 下限500m -->
</select_rules>
```

**内部实现**: 构建端点连通图 → 死胡同迭代剪枝 → select_rules 按 grade 分级长度过滤。

### 8.2 BuildingSelectAlgorithm — 建筑选取

**功能**: 按重要性和面积选取建筑，支持典型化（保留建筑群形状特征）。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `method` | string | importance_area | 选取方法 |
| `min_area` | double | 150.0 (m²) | 最小面积 |
| `importance_field` | string | ClassID | 重要性字段 |
| `typification` | bool | true | 典型化（删除单体建筑，保留群体轮廓） |
| `typification_grid` | double | 100.0 (m) | 典型化格网大小 |

### 8.3 HydroNetworkSimplifyAlgorithm — 水系缩编

**功能**: 简化河流/湖泊，塌陷辫状水系为单一河道。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `min_river_length` | double | 100.0 (m) | 最小河流长度 |
| `min_lake_area` | double | 2000.0 (m²) | 最小湖泊面积 |
| `braided_stream_collapse` | bool | true | 辫状水系 → 单一河道 |
| `preserve_flow_direction` | bool | true | 保持流向 |

### 8.4 SettlementGeneralizeAlgorithm — 居民地缩编

**功能**: 合并 + 简化居民地面要素。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `min_area` | double | 500.0 (m²) | 最小面积 |
| `merge_distance` | double | 30.0 (m) | 合并距离 |
| `outer_boundary_simplify` | bool | true | 简化外部边界 |

### 8.5 LandformSimplifyAlgorithm — 地貌简化

**功能**: 等高线 + 面积过滤。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `min_contour_interval` | double | 10.0 (m) | 最小等高距 |
| `min_area` | double | 5000.0 (m²) | 最小面积 |

### 8.6 BoundarySimplifyAlgorithm — 境界线简化

**功能**: DP 算法简化 M/N 类行政/自然边界。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `tolerance` | double | 20.0 (m) | 简化容差 |

## 9. Stage 5: 冲突检测与处理

**Stage ID**: `conflict`  
**目的**: 检测缩编后出现的空间冲突（符号压盖、几何重叠、间隙过窄），通过位移/收缩修复。

### 9.1 SymbolConflictDetectAlgorithm — 符号冲突检测

**功能**: 考虑线符号宽 + 注记缓冲区，检测图层间的符号化压盖。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `line_symbol_width` | double | 0.3 (mm) | 目标比例尺下线符号宽度 |
| `label_buffer` | double | 2.0 (mm) | 注记缓冲区（图上 mm） |

**内部流程**:
1. 图上 mm → 实地 m 换算（比例尺分母 / 1000）
2. 线图层 buffer(lineSymWidth)，面/点图层 buffer(labelBuf)
3. 逐图层 Union → 两两检查交叠 → 输出 `symbol_conflict.shp`

### 9.2 GeometryConflictDetectAlgorithm — 几何冲突检测

**功能**: 检测面要素之间的重叠（面积 > 阈值）和间隙（距离 < 阈值）。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `min_gap` | double | 0.2 (mm) | 目标比例尺下可辨识最小间距 |
| `min_overlap_area` | double | 0.5 (mm²) | 可容忍最小重叠面积 |

**输出文件**: `geom_conflict.shp`，严重程度分级：
- `polygon_overlap` → severity: **high** (高)
- `narrow_gap` → severity: **low** (低)

### 9.3 DisplacementResolveAlgorithm — 位移解决

**功能**: 将 aggressor（道路/管线）扩展后压盖的 victim（建筑）向外位移。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `method` | string | least_squares | `least_squares`(最小二乘: 位移量与侵入深度成正比) / `beam`(梁弯曲模型) |
| `max_displacement` | double | 50.0 (m) | 最大允许位移量（超限则不变） |

**冲突对**:

```xml
<conflict_pairs>
    <pair aggressor="a_tra" victim="a_bld" buffer="5.0" unit="m"/>
    <!-- 道路扩展5m → 压盖建筑 → 建筑位移 -->
    <pair aggressor="a_pip" victim="a_bld" buffer="3.0" unit="m"/>
    <!-- 管线扩展3m → 压盖建筑 → 建筑位移 -->
</conflict_pairs>
```

**内部流程**: aggressor Union → buffer → 相交检测 → 质心方向计算 → OGR 几何平移。

### 9.4 PolygonAdjustAlgorithm — 面膨胀/收缩

**功能**: 面间间距不足 `min_separation` 时，低优先级面负向 buffer 收缩。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `min_separation` | double | 0.3 (mm) | 最小间距（图上 mm） |
| `edge_snap` | bool | true | 收缩后面边界吸附到道路/河流边界 |

**优先级** (低→高): A(建筑) < C(居民地) < D/E(道路/管线) < F(水系) < J(地貌) < M(政区) < N(自然)

### 9.5 ConflictReportAlgorithm — 冲突报告

**功能**: 汇总前序算法产生的 `*_conflict*.shp`，输出统一报告（SHP + CSV）。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `output_format` | string | SHP | `SHP` / `CSV` (同时输出两种) |
| `include_resolved` | bool | true | 是否包含已解决的冲突 |

**输出文件**:

| 文件 | 说明 |
|------|------|
| `conflict_summary.shp` | 统一冲突点图层（含6个属性字段） |
| `conflict_summary.csv` | CSV汇总表（Excel可打开） |

**冲突记录字段**:

| 字段 | 类型 | 说明 |
|------|------|------|
| `conf_type` | String(64) | 冲突类型: symbol_overlap / polygon_overlap / narrow_gap |
| `severity` | String(32) | 严重程度: high / medium / low |
| `aggressor` | String(128) | 源图层名 |
| `victim` | String(128) | 目标图层名 |
| `descript` | String(254) | 冲突描述 |
| `resolved` | String(16) | 是否已解决: resolved / unresolved |

## 11. 数据流转

### 11.1 管线内数据传递

```
                    输入 (SHP 目录 或 DB → Temp SHP)
                               │
                    ┌──────────┴──────────┐
                    │  PipelineExecutor    │
                    │  工作目录:           │
                    │  %TEMP%/mpqis_gen_*  │
                    └──────────┬──────────┘
                               │
              ┌────────────────┼────────────────┐
              ▼                ▼                ▼
      Stage 1 输出     Stage 2 输出      ...  Stage 5 输出
    (子目录: preprocess) (子目录: merge)    (子目录: conflict)
              │                │                │
              └────────────────┼────────────────┘
                               │
                               ▼
                     最终输出目录
                    (SHP + gpkg + DB)
```

### 11.2 算法间传参

同一 Stage 内的算法**顺序执行**，前一个算法的输出目录作为后一个的输入：

```
Stage/merge 目录 (_algo_0 BuildingMerge  →  _algo_1 WaterMerge  →  _algo_2 VegetationMerge)
                         │                        │                        │
                    结果回拷到 merge          结果回拷到 merge          结果回拷到 merge
```

### 11.3 文件命名约定

- 算法按文件名前缀识别图层大类: `{A~N}_*.shp`
- 水系检测: `F` 前缀 或 `n_hyd` 前缀
- 植被检测: `L` 前缀 或 `n_agr` 前缀
- 境界检测: `M` 或 `N` 前缀

## 12. 故障排除

### 12.1 常见错误

| 错误信息 | 原因 | 解决方法 |
|----------|------|----------|
| `XML 解析失败` | XML 格式错误（`--` 在注释内、标签不闭合） | 检查 XML 语法，注释用 `====` 代替 `----` |
| `SHP_FILE_COUNT_IS_ZERO` | 输入目录无 .shp 文件 | 确认数据路径正确 |
| `GDALOpenEx 返回 NULL` | 文件路径不存在或权限不足 | 检查路径是否存在、文件是否被占用 |
| `ogr2ogr 导入失败` | 数据库连接信息错误 / 无 ogr2ogr | 验证连接参数；确认 GDAL 在 PATH 中 |
| `GEOS 操作失败` | 几何无效（无效环、非简单面） | 在 XML 中开启 Stage 1 的 TopologyFix + GeometryNormalize |
| `算法未注册` | XML 中 `class` 属性拼写错误 | 对照本文档的算法类名（如 `BuildingMergeAlgorithm`） |

### 12.2 推荐执行策略

1. **首次运行**: 仅开启 Stage 1 (preprocess)，检查输出质量
2. **逐阶段验证**: `preprocess → 合格` → `merge → 合格` → ... 逐步激活
3. **参数调优**: 从小容差开始（`tolerance=1.0`），逐步放宽直至满足目标比例尺要求
4. **规模测试**: 在完整数据集运行前，建议先用 AOI 裁剪小块区域（`<area_of_interest>`）验证效果

### 12.3 性能建议

| 要素数量 | 建议 |
|----------|------|
| < 1000 | 所有 Stage 全部开启 |
| 1000 ~ 10000 | 关闭 GeometryConflictDetect 的 N×N 配对（或对图层分组限制） |
| > 10000 | 建议先按图层大类分批处理，分次执行不同 Stage |
